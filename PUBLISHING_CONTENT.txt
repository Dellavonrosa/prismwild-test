PRISMWILD LIVE CONTENT PUBLISHING
=================================

FIRST TIME ONLY (moving from v0.15.23 to v0.15.26)
1. Replace the files in your local GitHub Desktop prismwild-test folder with the contents of this v0.15.26 build.
2. Make sure the new folder content/ exists and contains prismwild-content.js.
3. In GitHub Desktop, Commit to main, then Push origin.
4. Refresh the public Prismwild site. The current published custom species should load automatically.

FUTURE MONSTER / CONTENT UPDATES (NO GAME REBUILD NEEDED)
1. Open the Admin panel in Prismwild.
2. Create or edit your monster normally.
3. Check "Include this custom species in Live Content export" only when it is ready for the public game.
4. Click "Export Live Content" in Admin.
5. Your browser downloads prismwild-content.js.
6. In your local GitHub repository, open the content folder.
7. Replace content/prismwild-content.js with the newly downloaded file.
8. Open GitHub Desktop.
9. Commit the change with a short message such as "Add NewMonsterName".
10. Click Push origin.
11. Refresh the public site. Players will receive the new content revision without resetting their saves.

DRAFTS
- New custom monsters default to Draft.
- Draft monsters stay in your local Admin browser and are NOT included in Live Content exports.
- Existing built-in monsters are always part of the game and do not use the Draft/Published switch.

BACKUPS
- "Export Admin Data" is still the full workshop backup.
- "Export Live Content" is the public publishing file.
- Keep occasional Admin Data backups somewhere safe. Live Content is for publishing, not your only backup.

IMPORTANT STATIC-HOSTING NOTE
The Admin panel cannot directly modify GitHub Pages. Publishing still requires replacing prismwild-content.js in the repository and pushing it through GitHub Desktop. This avoids putting GitHub credentials inside the public game code.


IMPORTANT HOTFIX NOTE
---------------------
v0.15.26 fixes the Live Content loader. v0.15.26 could export content correctly but did not load content/prismwild-content.js at startup.


CUSTOM ATTACKS
--------------
Custom attacks have their own Published checkbox in Admin > Attacks. A published custom monster that uses a custom Signature Attack cannot be exported until that attack is also Published. This prevents a live monster from referencing a move that players do not have.

LIVE CONTENT LOADING
--------------------
Prismwild v0.15.26 revalidates content/prismwild-content.js at startup so GitHub Pages updates are picked up promptly. Admin shows the loaded Live Content revision so you can verify that the public site received the newest pack.
